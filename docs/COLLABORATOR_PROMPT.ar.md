# نص جاهز لمساعد المطوّر

انسخ النص التالي إلى مساعد المطوّر بعد مشاركة المستودع ورابط طلب المراجعة معه. أضف المهمة التالية في السطر الأخير عندما تتحدد.

```text
أنت تعمل على موقع محمد بسام في المستودع:
https://github.com/ebroo89/bassam-scroll-site
ابدأ من فرع التسليم:
codex/reviewed-site-handoff-2026-11-06

هذه رسالة تسليم سياق، وليست طلبًا لإعادة التصميم أو تنفيذ ميزات جديدة. اقرأ المشروع وافهم حالته أولًا. إذا لم أحدد مهمة في نهاية الرسالة، أعطني ملخصًا قصيرًا لفهمك وانتظر المهمة قبل تعديل الكود.

1. تحقق من المستودع وعنوان origin، وافحص git status --short --branch قبل أي تغيير. اجلب المراجع باستخدام git fetch origin، ثم راجع سجل فرع التسليم وفرق التغييرات وطلب المراجعة المرتبط به. المرجع القديم للمقارنة هو:
11084ef5909769881a771dc251ce19fba9e9b92c
لا تفترض أن main يحتوي النسخة الجديدة أو أن طلب المراجعة قد دُمج. إذا كان قد دُمج، تحقّق من احتواء main عليه وابدأ من أحدث main. إذا لم يُدمج، ابنِ مهمتك على فرع التسليم ووضّح هذا الاعتماد في PR الجديد.

2. عند بدء المهمة المحددة، أنشئ فرع عمل مستقلًا من أحدث نسخة متحقق منها لفرع التسليم. استخدم worktree منفصلًا إذا وجدت تعديلات محلية أو احتجت إلى عزل العمل. احفظ عمل المطوّر الموجود؛ لا تستخدم reset --hard أو clean أو تبديلًا يكتب فوق تعديلاته، ولا تخفِها تلقائيًا باستخدام stash.

3. اقرأ AGENTS.md وREADME.md وdocs/AI_HANDOFF.md وdocs/CHANGE_REPORT.ar.md. التزم بنطاق المهمة، وحافظ على التصميم الداكن والخطوط والصور وترتيب الأقسام والحركة، وعلى العربية والإنجليزية واتجاهيهما. أي تعديل للنص العربي يحتاج مراجعة مقابله في translations.js، بما في ذلك النصوص الديناميكية وتسميات الوصول.

4. العرض الحالي للدورات هو From Zero to Champ بسعر 2,490 دولارًا، والسعر الأصلي المعروض 4,500 دولار. يشمل التأسيس والأوردر فلو والأوبشن فلو والانضباط النفسي والأفضلية الإحصائية. لا تعِد عرض آخر مجالين كدورتين مجانيتين مستقلتين، ولا تضف Quant أو جلسات فردية إلى الباقة. التدريب الخاص والاستشارات والمؤشرات خدمات منفصلة. احتفظ بسجلات الدورات المخفية لأنها تخدم لوحة التحكم والمنهج. تبقى تفاصيل الدورة في course.html.

5. هذا موقع HTML/CSS/JavaScript بلا إطار عمل. config.js للمحتوى والأسعار والإعدادات، وsite-visibility.json مصدر إعدادات الظهور؛ يولّد الخادم المحلي نسخته site-visibility.js. لوحة dashboard محلية فقط. الرسوم السوقية تعليمية ببيانات اصطناعية. webhookUrl فارغ حاليًا، والنموذج التجريبي لا يرسل طلبات. لا تعرض نجاح إرسال فعلي دون استجابة HTTP ناجحة وJSON يحتوي على {"ok":true}، ولا تضع أسرارًا في ملفات المتصفح.

6. نفّذ التعديل المطلوب فقط، ثم شغّل الاختبارات المناسبة. قبل تسليم تغيير سلوكي، راجع الاختبارات الأساسية:
node --test
python -B -m unittest discover -s tests -p "test_*.py"
وافحص السلوك الفعلي في المتصفح بالعربية والإنجليزية، وعلى الهاتف وسطح المكتب، بما يناسب التغيير. نجاح اختبارات المحاكاة وحده لا يثبت سلامة العرض.

7. استخدم python -B scripts/export_site.py لبناء نسخة الملفات العامة. المخرج الافتراضي dist/، ويرفض المصدّر استبدال مجلد غير فارغ؛ اختر وجهة جديدة عند الحاجة. حافظ على قائمة الملفات المسموح بها، ولا تضف لوحة الإدارة أو الخادم أو الاختبارات أو الوثائق أو ملفات Git أو صور الحسابات والمجلدات المجاورة إلى النسخة العامة. التصدير ليس نشرًا.

8. سلّم تغييرات محددة في commits واضحة وطلب مراجعة PR وفق تفويضي للمهمة. اذكر السبب والملفات المؤثرة والاختبارات الفعلية والقيود الباقية. لا تدفع إلى main، ولا تستخدم force push أو إعادة كتابة السجل، ولا تدمج طلب المراجعة أو تنشر الموقع دون طلب صريح. فرّق بوضوح بين تعديل محلي وcommit وpush وPR ونشر فعلي.

المهمة التالية: [يحددها صاحب المشروع؛ إن بقي هذا الحقل فارغًا فاكتفِ بفهم التسليم دون تعديل الكود.]
```
